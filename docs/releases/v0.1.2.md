## SSH usernames and saved passwords

- Saved connection profiles retain the remote username and can now store the SSH password in the system keyring: Secret Service on Linux and Keychain on macOS.
- In the connection editor, enter the masked **SSH password**, move to **Save password**, press Space to enable it, then press Enter to save. Leave the password blank to keep an existing one, enter a replacement to update it, or disable saving to remove it. Deleting a profile also removes its credential.
- Direct and HTTP CONNECT connections use the saved password on login and reconnect. A saved password is tried once per connection; missing credentials, an unavailable keyring, or a rejected password fall back to hidden manual input.
- Press **m** on a connection or disconnected tab for one-time manual authentication. SSH jump hosts, custom OpenSSH routes, private-key passphrases, and multi-factor authentication use manual input.

Passwords are not written to configuration files, command-line arguments, environment variables, temporary files, or terminal output. OpenSSH host-key confirmation and changed-host-key rejection remain in place. Existing configurations continue to load without migration.

Linux requires an accessible, unlocked Secret Service to save passwords; manual login works without it. HTTP proxy passwords and quick connections are not saved.

## SSH 用户名与密码保存

- 在连接编辑表单中填写用户名和遮罩显示的 **SSH 密码**，移动到 **保存密码**，按空格开启，再按 Enter 保存。Linux 使用 Secret Service，macOS 使用 Keychain。
- 密码留空保留已有凭据；输入新密码可替换，关闭保存开关可清除，删除连接同时清理对应凭据。
- 直连和 HTTP CONNECT 支持自动登录与重连。保存的密码每次连接最多尝试一次；凭据丢失、密钥环不可用或密码错误时改为手动输入。
- 在连接列表或已断开的标签中按 **m**，为本次连接使用手动认证。跳板连接、私钥口令及多因素认证继续手动输入。
- 密码不写入配置、进程参数、环境变量、临时文件或终端输出。保留主机指纹确认及主机密钥变化拒绝，兼容已有配置。

## Downloads

Packages are provided for Linux x86_64, macOS Intel, and macOS Apple Silicon. Verify the archive against `SHA256SUMS` before extracting. macOS binaries are not signed or notarized.
